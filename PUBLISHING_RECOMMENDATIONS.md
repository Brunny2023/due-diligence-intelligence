# Publishing Recommendations — Rebased Final

## Recommended delivery model

Use **Run on Capafy** with **Run on Demand** execution, subject to the live Publisher interface at submission. The Skill’s value is its evidence-calibrated diligence and decision-intelligence methodology. It has no requirement for a persistent backend, database, scheduled job, polling loop, background worker, idle model process, payment flow, subscription-management system, or package-managed request entitlement.

## Positioning

Position the Skill as an **evidence-aware business due-diligence and decision-intelligence workflow**, not a generic company-summary agent, standalone LLM infrastructure product, legal/financial recommendation agent, or transaction-execution service. Its implemented differentiators are source-family and source-independence treatment, reconciliation-aware discrepancy analysis, the Diligence Decision Map, prioritized evidence requests, risk-linked management questions, opportunity and scenario registers, what-would-change-the-conclusion analysis, objective-specific transaction impacts, evidence-calibrated qualitative assessments, and structured executive findings that preserve verification status.

## Rebased technical boundary

The V2.1 methodology is the authoritative package foundation. The Skill remains LLM-agnostic and uses a host-provided LLM only for contextual interpretation and synthesis when available. It does not implement or require provider/model selection, API authentication, credential storage, credential hosting, endpoint configuration, independent inference service, provider routing, provider fallback, browser integration, API-key setup, or provider-specific deployment testing.

The retained V2.2 improvements are provider-agnostic: a static credential/network-boundary scanner, security regression coverage, strengthened Run-on-Demand documentation, and an explicit separation between host runtime responsibilities and the Skill’s evidence/reasoning responsibilities.

## Pricing and user-request principle

The intended commercial configuration may be **US$19/month** with a target allowance of **60 substantive user investigation requests per month**, but the Skill does not implement, count, enforce, or bill that entitlement. One substantive investigation is one user request. Internal LLM reasoning, document processing, claim extraction, validation, report assembly, retries, and quality checks are not separate user requests for this Skill.

Before submission, confirm the platform’s current pricing options, native monthly request-limit field, applicable fees, refund/support expectations, and listing semantics. If the publisher elects to offer the intended terms, configure the available platform-native control rather than adding an application-level counter.

## Category, tags, disclosures, and review

Select categories and tags only from the live Publisher-interface presets. If currently offered, evaluate a closest semantic category such as **Business Intelligence** or **Company Research** and tags such as **Due Diligence**, **Business Intelligence**, **Risk Analysis**, **Company Research**, and **M&A**. Do not submit invented category or tag values.

Before submission, enter a valid support email; select the live delivery, pricing, and request-limit settings; declare the actual host-runtime model/provider and any third-party data services in the platform fields; provide required data-handling notices; complete platform test cases; and verify the Agent Card, data-sharing declaration, LLM runtime disclosure, compliance checklist, and final validation report. The package is prepared for review but does **not** claim platform approval.

## Rebased review and security controls

The package’s deterministic helpers are standard-library-only and make no network calls. User-supplied material is treated as untrusted data. The package includes input validation, prompt-injection indicators, evidence-boundary controls, document-only mode, qualitative evidence-calibrated assessment controls, deterministic executive-summary consistency checks, and a static scan for hard-coded credential patterns or network-capable deterministic helpers.
