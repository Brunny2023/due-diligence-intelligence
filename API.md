# HTTP API

The Python service is started with `python3 -m app.api.server`. It uses the standard-library `ThreadingHTTPServer` and listens on `0.0.0.0:8000`.

| Method | Route | Request | Success response | Error behavior |
|---|---|---|---|---|
| `GET` | `/health` | None | JSON health object | `404` for unknown routes |
| `GET` | `/demo` or `/` | None | HTML demo | `404` for unknown routes |
| `POST` | `/api/query` | JSON object with `question` and optional `top_k` | `GroundedAnswer.as_dict()` JSON | `400` for invalid/missing question; unhandled provider failures may surface as proxy `502` |

## `GET /health`

The implementation returns:

```json
{
  "ok": true,
  "retrieval_mode": "live-pinecone",
  "embedding_model": "openai/text-embedding-3-small",
  "upserted_chunks": 5,
  "pinecone_available": true
}
```

Values are runtime-dependent. Offline mode reports `offline-demo` and `pinecone_available: false`.

## `POST /api/query`

Example request:

```json
{
  "question": "What evidence exists regarding Northstar's revenue performance and growth?",
  "top_k": 5
}
```

`top_k` is converted to an integer and clamped to the range 1–10.

The response is generated by `GroundedAnswer.as_dict()`:

```json
{
  "question": "...",
  "finding": "...",
  "confidence": "...",
  "evidence": [
    {
      "rank": 1,
      "score": 0.91,
      "document_id": "audited-financials-2024",
      "document_name": "Audited Financial Statements FY2024",
      "document_type": "audited_financials",
      "section": "Revenue",
      "source": "...",
      "text": "..."
    }
  ],
  "missing_evidence": ["..."],
  "inference": "...",
  "provider": "OpenRouter/anthropic/claude-opus-5",
  "live_retrieval": true
}
```

The exact evidence metadata depends on the retrieved chunk. The implementation can include `page_number`, `date`, `evidence_tier`, and `topic` when present in the source data.

## Validation and errors

An empty or missing `question` returns HTTP 400 with a JSON `error` field. Malformed JSON and invalid `top_k` values are also handled by the current `400` path.

The current handler catches validation exceptions but does not catch arbitrary provider exceptions. During final reasoning validation, OpenRouter returned HTTP 402 because the available token/credit budget was insufficient; the hosting edge surfaced the failed request as HTTP 502. This is documented as the current provider boundary, not as evidence that the retrieval architecture failed.

CORS is granted only to `https://ddi.maindev20.workers.dev`; `OPTIONS` requests from other origins return HTTP 403. Provider credentials are never included in API responses.
